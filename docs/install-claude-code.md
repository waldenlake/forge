# Claude Code Installation — Context Management Recommendations

## Recommended Environment Variables

Set these in your shell profile (`.bashrc`, `.zshrc`, or system environment):

```bash
export CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=60
export CLAUDE_CODE_DISABLE_1M_CONTEXT=1
```

### Why `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=60`

Claude Code's default auto-compact threshold is ~95% of the context window.
By that point, the model has already been working in a degraded state for
many thousands of tokens. Setting the threshold to 60% ensures compaction
happens while there's still substantial headroom, and forge's PreCompact
hook can inject the handoff seed before context quality deteriorates.

### Why `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`

The 1M context window gives the illusion of unlimited context but
dramatically increases latency and cost per message. For forge workflows
(where handoff.md + auto-resume can losslessly restore state after
compaction), the 200k window with aggressive compaction gives better
throughput: each message is faster, and compaction + /resume is nearly
free compared to processing 800k+ tokens of stale history.

## Hook Configuration (auto-generated by `forge init`)

When `forge init` detects a `.claude/` directory, it automatically adds
PreCompact and PostCompact hooks to `.claude/settings.json`:

```json
{
  "hooks": {
    "PreCompact": [{
      "matcher": "",
      "hooks": [{ "type": "command", "command": ".forge/bin/forge handoff:get" }]
    }],
    "PostCompact": [{
      "matcher": "",
      "hooks": [{ "type": "command", "command": ".forge/bin/forge handoff:get" }]
    }]
  }
}
```

These hooks inject the current handoff state (feature, task progress, next
task) into the compaction context, ensuring that after compaction the model
can run `/resume` and pick up exactly where it left off.
